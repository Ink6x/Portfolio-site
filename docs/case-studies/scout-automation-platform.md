# 求人スカウト業務の自動化プラットフォーム

> 受託（業務委託）案件 / GCP・Django・Terraform
> 守秘義務に配慮し、クライアント名・プロダクト名・媒体名を伏せ、公開可能な範囲で内容を再構成しています。コードは非公開です。

## 概要

複数の求人媒体にまたがるスカウト送信・応募者管理業務を自動化する、GCP 上のプラットフォーム開発に業務委託として参画しました。プラットフォーム全体は、Playwright によるブラウザ自動操作ロボット群（チーム開発）が媒体を横断して並列稼働し、その結果を扱う管理 Web アプリケーションとクラウド基盤で構成されています。

本ケースで私が主に担当したのは、**ロボットが扱う応募者データとスカウト業務を管理する Web アプリケーション（Django）**、および**それを支えるクラウド基盤（インフラ・CI/CD・DB）**です。

- **役割:** Backend / Infra・CI-CD / System Design
- **担当期間:** 約6か月（要件整理〜実装〜デプロイ〜運用）
- **規模:** プラットフォーム全体で 15 以上の求人媒体に対応

## 技術スタック

| レイヤー | 技術 |
|---|---|
| 管理アプリ | Python / Django / Django REST Framework |
| RPA実行（連携） | FastAPI / Playwright |

| インフラ | Terraform / Cloud Run / GCP |

| CI/CD | GitHub Actions / Artifact Registry |

## 課題

求人スカウト業務は媒体ごとに管理画面・仕様・データ構造がばらばらで、対応媒体を増やすたびに人手の作業と実装コストが積み上がる構造でした。さらに当初は GCE 上で稼働しており、環境の追加やデプロイに手間がかかるうえ、本番と検証環境が分離されていないため、リリースのたびにリスクを伴っていました。

**媒体拡張に強く、安全にデプロイできる基盤へ作り替えること**が課題でした。

## 取り組んだこと

### 1. 新規媒体連携の一気通貫実装

新規 3 媒体の連携を、Django 上で**データモデル・スカウト送信 API・応募者管理画面・DB マイグレーションまで一気通貫**で実装しました。

- 媒体ごとに異なる応募者 ID 体系や項目を、共通のデータモデルへ正規化
- スカウトの重複送信を防ぐバリデーション、送信可否のトグル、下書き編集 API など運用に必要な機能を整備
- 既存媒体の構造に揃えることで、**媒体追加が定型作業として回る状態**を実現

### 2. インフラ移行と staging 環境の新設

- 稼働環境を **GCE から Cloud Run へ移行**
- Cloud SQL への接続を **Cloud SQL Connector 方式へ統一**
- 本番から**完全に独立した staging 環境（Cloud SQL / Cloud Run）をゼロから構築**し、検証してから本番へ出すデプロイフローを確立
- IAM・サービスアカウント・ネットワーク・Cloud Logging を含む構成を**すべて Terraform でコード管理**
- 最小インスタンス数を 0 にするなどのコスト最適化

### 3. CI/CD 自動化と DB 運用

- GitHub Actions で **Artifact Registry と連携したデプロイを完全自動化**（イメージ未存在時のフォールバックなど、運用の引っかかりも解消）
- DB マイグレーションがコンテナ起動時に安全に流れるよう entrypoint を整備し、環境間のスキーマ不整合を解消
- **ER 図のドキュメント化**を行い、チームがデータ構造を把握しやすい状態を整備

## 成果

- 新規媒体 3 種を本番に追加し、**媒体拡張が定型化**された
- Cloud Run への移行と staging 環境・CI/CD の自動化により、**検証を挟んだ安全なデプロイが日常的に回る体制**を整えた
- インフラは Terraform でコード化され、**再現性のある環境管理**を実現

## 学んだこと

- **拡張性は「定型化」から生まれる** — 媒体ごとの差異を共通モデルへ正規化し、既存構造に揃えることで、追加実装を属人化させない仕組みにできた。
- **環境の分離はリリース速度を上げる** — 独立した staging を用意し IaC で再現性を担保したことで、「壊さずに速く出す」運用が可能になった。
- **チーム開発における担当境界の設計** — RPA 実行エンジン（チーム）と管理アプリ・基盤（自分）の責務を分け、データモデルを接点として連携させることで、並行開発を成立させた。
